# 产品说明

## 1. 产品定位

DSH Companion Bot 是一个“持续存在的个人数字角色”，而不只是聊天窗口。她运行在用户的 Mac mini 上，通过手机 App 与用户保持联系，并能把自己的经历、状态和内容以动态形式呈现。

项目采用渐进式建设：早期完成可靠的聊天与人格连续性，中期加入动态和声音，长期接入虚拟形象、实时视频、游戏及其他媒体能力。

## 1.1 产品总纲：一个角色，多个场景，统一内核

最终目标是一个长期存在、能够处理文字与语音、拥有形象与行动、会积累经历的数字角色，而不是多个平台各自运行的聊天插件。

- **总纲参照**：以本地 `Cortico-main.zip` 与 `Coopanion-main.zip` 已展示的真实游玩、语音、直播和角色行动为产品参照；借鉴机制与验收标准，不把参考项目的演示当成本项目进度，也不整套替换 DSH。AIRI 主要用于 Live2D 与部分场景机制参考。
- **一个角色核心**：人设、中央记忆、世界状态、权限、任务与素材元数据属于同一个角色。手机、桌面、游戏、动态和直播是不同入口，不复制人格核心。
- **Session 分离**：手机聊天、Minecraft、动态、桌宠、记忆整理和自主动作使用各自执行上下文。跨场景共享的是经过授权的记忆与事件，不是整段历史。
- **World 可扩展**：Minecraft、B站、桌面、手机和未来功能以连接器接入。每种连接器声明观察、动作、权限、健康状态和释放方式，故障不阻塞其他 World。
- **Provider 可替换**：普通 TTS、实时 TTS、ASR、歌唱、图像和存储是不同能力，不以一个模型名称包办全部媒体需求。
- **行动必须有证据**：意图、授权、实际工具回执、世界状态与最终结果分别记录。角色说“我做过”不能替代真实执行结果，未完成的动作不能写成经历。
- **主人保留控制权**：可以查看来源、修改人设与记忆、暂停任务、撤销权限、清理素材和回退版本。自主性不能以失去可控性为代价。

## 2. 目标用户与使用场景

首版只服务设备所有者，不设计公开账号体系或多用户社区。

核心场景：

1. **随时聊天**：手机通过 Tailscale 连接 Mac mini，进行流式文字对话。
2. **连续关系**：角色记得用户偏好、重要事件和共同经历，用户可纠正或删除记忆。
3. **浏览动态**：以类似 Twitter 的时间线查看角色发布的文字、图片、语音及活动记录。
4. **互动回复**：用户回复动态，角色结合上下文和记忆继续交流。
5. **主动行为**：角色在受控频率下主动问候、总结经历或发布动态。
6. **语音交流**：角色发送语音消息，后续升级为实时语音对话。
7. **角色展示**：角色主页展示头像、简介、当前状态及后续虚拟形象。
8. **共同活动**：后续在 Minecraft 等环境中执行任务，并把经历沉淀为记忆和动态。

## 3. 手机 App 信息架构

默认采用五个主要入口，MVP 可先隐藏未实现页面：

| 页面 | 主要功能 |
| --- | --- |
| 首页 | 角色动态、用户动态、回复、活动卡片 |
| 聊天 | 流式文字、历史会话与按需语音；后续加入图片与实时通话 |
| 发布 | 用户发布动态、图片或状态 |
| 通知 | 回复、主动消息、任务结果、能力异常 |
| 她的主页 | 人设摘要、头像、在线状态、记忆管理、能力状态 |

聊天和动态不是两个独立 Bot。二者必须调用同一个角色核心，并共享人设、记忆、用户身份和任务状态。

## 4. 角色连续性

角色由以下信息共同构成：

- **固定人设**：身份、价值观、表达风格、背景与行为边界，独立于任何 Session。
- **关系设定**：她与用户的关系、称呼和互动边界。
- **中央记忆**：用户事实、偏好、共同经历、角色自己的经历，支持共享/场景私有、候选、修订、遗忘与恢复。
- **长期场景**：聊天、游戏、任务和话题分别以 `contextId` 归属，可并行绑定不同 Session。
- **当前状态**：各场景在线、忙碌、正在游戏、实时通话等可展示状态。
- **近期目标**：由用户明确设置或受控生成的短期目标。
- **能力配置**：已启用的 TTS、游戏、媒体等连接器。

人设应有版本号、更新时间和变更记录。动态状态不得直接改写固定人设，场景私有记忆不得因共享或跨场景召回而泄露。重开或更换 Session 不应重置角色身份与中央记忆。

## 4.1 记忆路由与人格成长

跨场景连续不等于共用一个无限增长的 Session。手机聊天、Minecraft、动态、记忆分析和自主行动各自使用独立执行上下文，通过稳定的 `contextId` 恢复场景；跨场景只检索经过授权的记忆和事件索引，不复制原始对话全文。

| 层 | 保存什么 | 使用方式 |
| --- | --- | --- |
| 原始日志 | 各 Session 的真实消息与工具记录 | 只服务对应场景，保留原始证据 |
| 摘要与事件索引 | 场景、时间、来源和重要活动指针 | 空闲整理、定位历史，不代替事实本身 |
| 中央记忆 | 可修订的事实、偏好、目标与共同经历 | 有限锚点加按相关性、权限和预算召回 |
| 自我笔记 | 角色对自己行为与互动方式的观察 | 最多 40 条有效项，旧项归档，保留历史 |
| 固定人设 | 身份、关系、表达与安全边界 | 版本化管理，不因一次对话自动改写 |

记忆必须区分用户明确表达、真实行为回执与模型推断，保留来源、置信度、反例和修订记录。重复提到一件事不自动提高事实置信度；长期保留取决于来源可靠性、重要度、独立证据、近期使用和场景匹配。遗忘保留 tombstone，主人可以纠正、撤回和回滚。

自我笔记不是不可修改的第二人格，也不证明角色具有人类情绪或意识。角色可以提出观察与人格调整建议，但不能借自主整理绕过来源、权限和回滚。自主活动只有在真实执行成功后，才可记作角色经历。

## 4.2 语音、形象与媒体生命周期

| 能力 | 产品合同 | 当前边界 |
| --- | --- | --- |
| 按需语音 | 从真实助手消息生成可重播、可鉴权读取的音频 | GPT-SoVITS v5 turbo 已在 Mac mini 验证；手机实际试听仍待验收 |
| 实时语音 | 增量文本、分段合成、有序音频、实际播放时钟与打断 | `0.13.0` 候选已实现分段实时化与取消回执，不是低延迟流式 TTS 或手机 RTC |
| 声画同步 | 音频能量驱动口型，受控动作意图驱动形象 | 不把“已请求播放”当作“正在说话” |
| 歌唱与音乐 | 独立歌声合成或声线转换 Provider，处理音高、节奏、伴奏和授权 | 不用普通 TTS 冒充歌唱，模型与素材另行选型 |

标准 Live2D 使用 `DeepSeek免费公皮.zip` 内的模型，先验证加载、基础表情、动作和停止回执。`大肥鱼合集_1.2` 是 YSM／游戏资源，不能直接放进 Live2D 渲染器；手机现有角色视频也只是展示素材，不是实时形象。模型、Cubism 运行时及第三方代码的权利分别处理，不随插件包重新分发未获授权的内容。

语音、图片、歌声、视频和生成物统一登记哈希、类型、来源、大小、最近使用时间和保留策略。先提供用量统计与清理预览，再清理明确可再生成的缓存；模型权重、角色原素材、参考声线、原始聊天、中央记忆与备份不进入自动垃圾清理。

## 5. 分期合同

每个阶段交付一条真实可验收的链路，参考项目的演示、名称或目录不代表本项目已经具备对应能力。详细进展和退出标准见 `docs/roadmap.md`。

| 阶段 | 交付目标 | 不提前承诺 |
| --- | --- | --- |
| M0～M2 地基 | 独立场景、中央记忆、手机聊天、动态、自主队列与按需语音 | 已有基础不等于 AIRI 全量能力；自主动态仍默认关闭 |
| M3a 角色生活基础 | 真实动态回应、自我笔记、媒体统计与预览、受限工具索引、Live2D 基础验证 | 不先堆复杂舞台、自动删文件或无约束人格改写 |
| M3b Minecraft | 连接、观察、聊天、跟随、导航和采集，再逐步扩展合成、建造与战斗 | 不把规划当完成，不默认开放 RCON、OP 或任意生成代码执行 |
| M3c 实时形象 | 可打断的实时语音、真实声画同步、Live2D 动作仲裁 | 不承诺未经实测的延迟、性能或 Mac 兼容性 |
| M4 跨场景与媒体 | 安全归档、手机文件与图片、视频浏览、实际资源与 token 用量 | 不用全文灌入刷视频，不把抓取量或估算当供应商账单 |
| M5 长期生态 | 歌唱、活动驱动的小家、直播展示、绘画与更多连接器 | 不牺牲核心聊天、权限、备份与回退能力 |

Minecraft 以实际 Coopcraft 服务端为目标，当前使用 Carpet fake player＋CBI＋本机受限控制台；主人仍通过 Tailscale 连接。无需另购微软账号，保留正版验证和白名单。Coopcraft 的进度、路径点等能力后续作为 World 事件来源，不假设它已经提供 AI 接口。先验证备份、真实连接和动作回执，再逐步扩大动作权限。

## 6. 数据、权限与资源边界

- **单用户私网**：默认仅所有者使用，通过 Tailscale 访问，不开放注册、公网端口或社交社区。
- **最小授权**：自主行为必须有事件来源、动作范围、预算、有效期和停止条件。帖子关联、记忆共享或工具可见都不自动扩大权限。
- **真实回执**：区分入队、执行中、成功、跳过、取消和失败；危险动作单独确认，支持停止、审计与恢复。
- **按场景控制成本**：常驻工具保持小而必要，扩展工具按场景与意图加载；原始日志、检索、摘要、媒体和供应商实际 token 分开统计。
- **素材与许可**：代码、模型权重、声音、Live2D、YSM 和视频分别核查权利。复用开源机制不等于直接复制其代码或资源。
- **资源隔离与降级**：语音、游戏、渲染和媒体服务失败时，文字聊天仍可使用；重计算与自动清理不能挤占核心服务或误删数据。

截至 2026-11-09，正式 Mac mini 上次核验运行 Companion `0.15.1`。已验收手机私网配对、流式聊天、图文动态和回复、跨场景共享记忆、基础 Live2D 动作，以及 Minecraft 连接、导航、原木采集和游戏经历回写。候选版本已加入多步授权营地、Android 连续语音与聊天附件、活动驱动的小家、B 站自主阅读和有出处的反思，以及独立歌唱和手机试听。本地 Seed-VC 已用大肥鱼参考音频完成真实音阶转换，完整歌曲、真机语音、正式服私聊与跟随、社区和自主舞台仍按各自标准推进。详细进展见 [开发路线](roadmap.md)。

## 7. 产品原则

1. **可解释**：记忆、主动行为和工具调用应能查看来源。
2. **可纠正**：用户可以修改人设、删除记忆、停止任务和禁用能力。
3. **可降级**：TTS、游戏或媒体服务故障时，文字聊天仍可用。
4. **最小权限**：连接器只获得完成其职责所需的权限。
5. **本地优先**：个人数据默认保存在 Mac mini，不上传到额外第三方服务。
6. **不伪造进展**：任务记录区分“已接收”“执行中”“成功”“失败”，不把投递当成完成。
7. **复用优先**：优先采用成熟组件，但以许可证、维护状态、隐私和可替换性为选型门槛。

## 3.1 视觉与动效参考（来自用户提供的 X 录屏）

录屏用于确认动效与交互节奏，不作为功能已经完成或可以直接使用第三方素材的证明。用户已明确纠正初版的方向误解：**主要界面不使用黑色，只希望参考 Twitter 的丝滑动效**。当前改为浅色主界面与低饱和蓝色角色区，不把聊天和动态混成同一列表。

- **信息层级**：以浅色背景、细分隔线和真实角色形象为主，不用大面积圆角卡片堆叠。名称、场景／时间、正文和次级操作分层显示；首页后续采用单列动态时间线，聊天仍保留左右消息气泡。
- **导航**：保留清晰的底部主导航与右侧主要操作按钮。个人资料、设置和场景切换可使用横向抽屉；回复和发布使用靠近底部的编辑区，不让弹层无目的地跳动。
- **视觉基准**：以白色或近白背景、深色主文本、柔和次级文本和低饱和蓝色角色区为方向，分割线弱于内容，错误与在线状态不能只依赖颜色区分。具体色值在真机上校验对比度，不宣称从录屏精确取色。
- **动效节奏**：横向抽屉和底部编辑区采用短促、可预测的滑动与淡入；初版以约 160～220ms 的 ease-out 为默认参考，保留滚动位置和当前任务状态。页面转场使用原生 Stack，按压反馈使用项目已有的 Reanimated，消息出现使用原生驱动动画；后台刷新不能反复播放整页入场动画。
- **可降级与可访问性**：点击目标不小于 44dp，图标提供文本标签；减少动态效果开启时应移除装饰性位移，不能影响聊天、取消、配对和错误提示。
- **素材边界**：不复制录屏中的头像、广告、文字或其他内容到安装包。用户另行指定的角色视频与静态帧按 `docs/references.md` 的来源记录使用；优先使用原生组件及项目已有的 Reanimated，不为了装饰效果再引入一套运行时。

默认不机械复刻 Twitter 的全部页面。配对与设备管理是工具流程，场景是角色活动的入口，聊天是对话，后续动态才是 Twitter 式时间线，四者分别保持合适的信息结构。

在第一版深色工程骨架的实际评审后，进一步明确以下优先级：

- **角色先于功能**：场景首页首先展示真实人设、用户指定的角色形象、记忆数量和主聊天入口，不让 `contextId` 等技术字段占据视觉中心。
- **参考但不拼装**：借鉴 Bluesky 的图标导航、文字层级和安全区域，以及 AIRI 的角色空间、紧凑操作与清楚状态；不复制品牌素材，也不引入与 Expo 应用无关的完整设计框架。
- **聊天遵循对话习惯**：连续同角色消息适当分组，自己的回复不重复显示“你”，回复等待与取消只在需要时出现，输入和发送保持同一行。
- **状态必须有依据**：记忆数和运行中场景数来自真实 API；“Host 已连接”不代表模型已配置，场景图标不代表 Minecraft 或定时任务已接入，空聊天不能伪造动态内容。
