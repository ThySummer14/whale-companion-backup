# 开发路线与验收标准

## 阶段原则

- 每个阶段都形成可运行、可备份、可回退的版本。
- 验收以真实链路和持久化结果为准，不以“代码已写完”为准。
- 每轮开发以至少 30 项可独立核验的改进、修复或阶段验收为交付目标。独立模块可以并行，版本打包前统一联调。
- 未通过 M0 的 dsh 接入验证，不并行开发语音、视频和游戏。
- 后续能力只能以独立适配器接入，不反向侵入手机聊天主链路。

## M0b1：场景会话与实时消息链路（已完成本机验收）

`v0.3.3` 已完成插件主动会话管理：

- 通过 `ctx.agents.create()` 为不同场景创建独立 Agent，通过 `ctx.agents.resume()` 恢复离线 Session。
- 使用 `ctx.agentDefaultModel.currentSelection()` 与 DSH 原生流程一致，不硬编码模型。
- `followup()` 接受真实用户消息，发送返回 accepted，不冒充模型已完成。
- `message.delta` 传递流式文本，`message.completed` 传递最终回复，`session/event` 提供持久完成状态。
- 取消产生 `message.cancel.requested` 和 `turn.aborted`，历史包含真实用户与助手消息。
- WebSocket 按 `contextId` 和 cursor 过滤、补发持久活动；瞬时不重放，历史用于最终内容对账。
- 停止 DSH 后恢复同一 Session 并再次发送成功，面板也可新建专用 Session 和恢复离线 Session。
- 未认证 WebSocket 握手返回 403，修复了默认模型缺失与空白 Session ID 两类真实问题。

本阶段不声称完成：原生手机配对、Tailscale、真实手机外网访问、后台推送、数据库备份恢复和长期驻留。

## M0b2：移动接入与剩余技术验证（进行中）

当前 `v0.8.0` 已完成一次性设备配对、独立设备 API、凭据哈希与撤销的设备链路实测，以及含非空记忆和真实聊天的全新 Home 恢复。Android 模拟器已完成配对、流式聊天、取消、历史恢复、半开连接重连和撤销后重新配对；Expo Web 导出和 iOS 原生构建已通过。Mac mini 的独立 Companion profile、DSH 用户服务、真实模型流式回复、真实动态和 Tailscale HTTPS/WSS 已实测通过，真实安卓手机也已配对并完成真实对话。新版动态首页、回复与性能调整仍待真实手机验收，不能将服务端自检等同于全部客户端验收。

### 目标

验证插件创建／恢复 Session、手机消息与流式回复、原生认证和 Tailscale 私网部署，并实际执行数据库备份恢复。

### 范围

- 插件创建／恢复 Session、发送消息、接收实时增量与持久完成事件。
- 自定义一元／流式 API，或明确采用受控 HTTP／WebSocket 替代方案。
- React Native 最小网络原型与可撤销设备配对。
- Tailscale Serve、HTTPS、Host 信任、认证、WebSocket 和断线游标恢复。
- SQLite 备份恢复与必要的 Schedule 验证。

### 完成标准

1. 手机或原生测试客户端在 tailnet 中完成认证并调用测试 API。
2. 一条消息完整经过“客户端 → 插件 → dsh Agent → 流式返回 → 持久化”。
3. 重启 dsh 后历史与插件领域数据可恢复，备份可还原到全新 profile。
4. 断开 WebSocket 后能够重连并恢复状态，不重复写入。
5. 插件卸载后没有遗留连接、计时器或可访问路由。

## M1：手机聊天 MVP

### 范围

- React Native／Expo 项目与服务端配对。
- 会话列表、聊天页、流式文字、取消和错误重试。
- 固定人设配置与版本保存。
- 基础用户事实记忆及查看、纠正、删除。
- 角色在线状态和基础健康页。
- 本地日志、数据备份与恢复说明。

### 明确不做

动态、TTS、实时语音、视频、Minecraft、主动任务、多用户。

### 完成标准

1. 用户可通过 Tailscale 在外网环境下与 Mac mini 中的角色聊天。
2. 回复逐字／逐段流式显示，取消后不会继续写入无效增量。
3. App 冷启动和 dsh 重启后，会话与人设保持连续。
4. 创建一条测试记忆，新会话能够按预期召回；删除后不再被当作事实使用。

## M4：媒体生命周期与跨场景体验

- 统一媒体清单、重复内容去重、来源索引、保留策略与清理预览。
- 在验证备份和回放后开放安全归档清理，原始聊天、模型、参考素材与备份不进入自动清理。
- 实时语音与视频通话分别评估传输协议、设备性能、状态同步和资源回收。
- 视频浏览采用来源许可、分段摘要、有限字幕与预算，不以全文注入方式刷视频。
- 手机文件、图片、语音和实际 token 用量展示，不将估算值当账单。

该阶段必须先做资源预算，避免 Mac mini 同时运行模型、媒体渲染和游戏时相互挤占。

**首个开发候选（v0.14.0，尚未部署或实机验收）：** schema v11 新增媒体删除墓碑。主人在本机工作台先预览，再明确确认删除；仅处理过期、可再生成的缓存，逐项核对路径、文件类型、大小和 SHA-256，缺失或变化文件跳过。实际删除后记录释放字节，后续扫描不复活墓碑；同名新文件可重新生成。模型、原素材、记忆、备份和保留项继续排除，未开放后台自动清理。真实文件与迁移验证通过。

**继续开发候选（v0.15.0，尚未部署或实机验收）：** schema v12 为动态增加图片附件。手机使用 Expo 相册选择与本地预览，上传 PNG/JPEG/WebP 且最大 10MB；服务端同时检查声明类型、真实魔数、大小和哈希，随机 ID 落盘并登记媒体清单。动态只保存媒体 ID，设备通过凭据加载图片，Mac 工作台使用同源管理地址展示同一附件。图片不进入 Session 正文或中央记忆，非图片类型与篡改读取被拒绝。真实文件、关联和迁移验证通过，移动端实际相册与图片显示仍需真机验收。

**图片链路（v0.15.1）：** schema v13 支持纯图片动态和回复。Android 模拟器已使用 DSH Go `0.1.0` 通过正式 Mac mini 的 Tailscale 链路验收配对、流式聊天、相册上传与双向读取。手机真机待复验。
